- (decision) Module communication: user chose 'No enforced module boundaries' over the Modulith sync/event hybrid. Binds: all 7 domain packages (auth, users, leave, approvals, balances, audit, notifications). Prevents: inconsistent mix of direct calls and events across modules. Rule: packages call each other's public service interfaces directly (plain Spring beans), synchronously, no application-event bus, no spring-modulith-starter-core runtime enforcement.
- (decision) Dependency hygiene follow-on from the module-boundaries decision: spring-modulith-starter-core and spring-modulith-starter-test are now dead weight (no ApplicationModules.verify(), no event listeners) -- spine recommends removing both from pom.xml rather than keeping unused scaffolding. Flagged as an AD, not re-asked (low-risk, reversible cleanup one level below the paradigm fork the user already decided).
- (decision) Auth model: user chose JWT bearer tokens over classic server-side sessions, to use the existing oauth2-resource-server starter. Binds: auth module, common security config, all protected endpoints. Prevents: a module hand-rolling its own token validation or session check. Rule: access JWT signed by the backend itself (self-issued, HS256, single backend keypair/secret from env var), short lived (e.g. 15 min), returned to the Angular client as an HttpOnly/Secure/SameSite=Strict cookie (never readable by JS, per PRD's cookie requirement). Pure stateless JWT cannot satisfy 'session timeout' (idle-based) or immediate revocation/lockout-during-active-session, so a server-side active-session registry (Postgres table active_sessions: token_id, user_id, last_seen_at, expires_at) is also required: every authenticated request (a filter) validates the JWT signature AND looks up/bumps active_sessions by token_id; idle >30min or missing row => 401. Login failure counting/lockout (5 tries/15min) stays on the users table (failed_logins, locked_until) exactly as the PRD already specifies, independent of the token question.
- (decision) Authorization placement: user chose a centralized AccessPolicy component over @PreAuthorize-per-module or Postgres RLS. Binds: all controllers across all 7 modules. Prevents: a module reinventing its own role/scope check, and RBAC gaps (the PRD's named risk) from inconsistent enforcement. Rule: a single shared AccessPolicy bean (in a thin 'security' package other modules depend on, nothing depends back) exposes methods like requireRole(role...), scopeToOwnRequests(userId), scopeToTeam(managerId) -- every controller method calls it first before touching its service; it is the only place role checks and id-scoping logic are written.
- (decision) Deliverable scope: spine only (ARCHITECTURE-SPINE.md + memlog), no extra walkthrough doc for this run, per user choice.
- (decision) Cross-module call convention (soft, not tool-enforced given the no-Modulith decision): a module may only be entered through its own public @Service interface. No module ever injects or queries another module's @Repository or JPA entity directly -- even controllers of module A call module B's service, never module B's repository. Binds: all 7 modules. Prevents: hidden coupling through shared repositories that would make the 'modular' packages a layering illusion.
- (decision) Same-transaction invariant: any service method that changes leave_requests/leave_balances state and must produce an audit_events row and/or a balance_ledger row does so inside one @Transactional method -- it calls AuditService/BalanceLedgerService directly before returning, never via @Async or an event. [ADOPTED] from PRD risk mitigation ('audit written in the service layer, inside the same DB transaction'). Binds: leave, approvals, balances, audit.
- (decision) Shared/common package rule: com.company.leave.common may contain only stateless utilities (working-day calculator), cross-cutting config (security, Flyway, Jackson), exception types, and the ProblemDetail error-advice. No entity, repository, or business-rule service may live in common -- that would create a silent cross-module dependency nothing catches (no Modulith verify() in this design). Binds: all modules + common.
