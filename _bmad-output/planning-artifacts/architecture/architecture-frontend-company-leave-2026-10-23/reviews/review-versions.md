# Review — Version Currency & API Reality

- **Target:** `ARCHITECTURE-SPINE.md` (company-leave-frontend, Angular 22 + Tailwind 4)
- **Reviewer lens:** version currency and API reality, checked against the live npm registry, the published package contents (`npm pack` + reading the `.d.ts` / `.mjs` / schematic files), angular.dev, tailwindcss.com, nodejs.org and Docker Hub. No training-data claims.
- **Date:** 2026-10-25

## Verdict

**Pass with corrections.** Every API the ADs depend on exists in the published 22.2.x packages and is stable (`@publicApi 22.0`), not experimental. There is one hard break and four stale or imprecise claims:

1. **Blocker:** `openapi-typescript@7.13.0` declares `peerDependencies: { typescript: "^5.x" }`, but Angular 22 requires TypeScript `>=6.0 <6.1`. A plain `npm install` fails with **ERESOLVE** (reproduced). The latest release, 7.13.0, has no TS 6 peer. An `overrides` entry fixes it, and the generator then works against the real `openapi.yaml` (reproduced).
2. `withFetch()` is **`@deprecated`** in 22.2.3. Fetch is now the default backend, so it should be dropped from `app.config.ts`.
3. TypeScript "6.x" is too loose. It must be **6.0.x**, since `typescript@latest` is now 7.0.2 and Angular rejects it.
4. Node "22 LTS or newer" is too loose. The supported range is `^22.22.3 || ^24.15.0 || >=26`, which excludes 23 and 25. Node 22 is in maintenance until 2027-04-30, so the build image should use **24** (or 26, which becomes LTS on 2026-10-28).
5. `nginx:1.27-alpine` is stale: last pushed 2025-04-16, on an EOL branch. Current stable is **1.30.6**, so use `nginx:1.30-alpine`.

There are also three precision notes (not errors): the Signal Forms directive is **`FormField` / `[formField]`**; `httpResource().value()` **throws** in the error state; and the spine's file-naming convention is the 2016 style, while `ng new` now defaults to 2025.

## Suggested spine edits (for the author)

- **Structural Seed, `app.config.ts`:** `provideRouter`, `provideHttpClient(withInterceptors([authInterceptor]))`, `{ provide: ErrorHandler, useClass: GlobalErrorHandler }`, `provideBrowserGlobalErrorListeners()`. Drop `withFetch()`.
- **Stack:**
  - TypeScript `6.0.x (~6.0.2; Angular 22 rejects 6.1 and 7.x)`.
  - Node `24 LTS (≥24.15); 22.22.3+ also supported; not 23/25`.
  - nginx `1.30-alpine`.
  - Add `postcss 8.5.x` next to Tailwind.
  - openapi-typescript `7.13.x, with an npm override because its typescript peer is ^5`.
- **AD-7:** "Set up via `ng new --style=tailwind` (or `ng add tailwindcss`), which writes exactly this config." Import `CdkTrapFocus` / `inject(LiveAnnouncer)` rather than `A11yModule`.
- **AD-8:** name the binding: `FormField` directive (`[formField]="f.field"`), optionally `FormRoot` on `<form>`.
- **AD-6 (Reads):** components must guard with `@if (res.error()) { <app-load-error/> } @else if (res.hasValue()) { … }`. Reading `value()` in the error state throws into `ErrorHandler`, which would double-report. `LoadError` and `GlobalErrorHandler` unwrap `HttpErrorResponse.error` to get the ProblemDetail.
- **AD-10:** add the `overrides` entry to `package.json`. Consider adding `required:` to response schemas as part of the existing backend follow-up.
- **Conventions:** state the file-name style guide (2016 vs the 2025 default) and the matching `ng new` flag.
