- (decision) AD-1 [ADOPTED] Paradigm: modular monolith, one Spring Boot deployable, organized as modules (identity, leave, approval, balance, audit, outbox, shared-kernel), each layered web-adapter / application / domain / persistence-adapter. Binds: all. Prevents: two units inventing different layering or extra services. Rule: each module exposes one application-service facade package; other modules call only that facade, never its repositories or entities.
- (decision) AD-2 Data ownership: every table has exactly one owning module; only the owning module writes it. Binds: all tables. Prevents: two owners of one entity (e.g. balance written by leave and by admin). Rule: cross-module reads go through the facade; no cross-module writes; each table name prefixed by owner module.
- (decision) AD-3 Dependency direction: web to application to domain; persistence adapters implement domain ports; domain has no Spring or JPA imports. Binds: all code. Prevents: domain logic leaking into controllers or repositories. Rule: enforced by ArchUnit test in CI; violation fails build.
- (decision) AD-4 State mutation: every leave or balance state change happens in one application-service method inside one DB transaction, which also writes the audit_event row and any outbox row. Binds: leave, approval, balance, audit, outbox. Prevents: two mutation paths or events written without audit. Rule: controllers and repositories never change leave_request or balance state directly; state transitions live in domain code only.
- (decision) AD-5 Audit trail: audit_event is append-only. PostgreSQL triggers reject UPDATE and DELETE on audit_event and access_log. Each row has actor id, action, entity type and id, before and after JSON, occurred_at UTC. Access reads of sensitive data (FR26) write access_log rows. Binds: audit module. Prevents: edited or deleted audit history. Rule: only the audit facade inserts audit rows; no other module writes these tables.
- (decision) AD-6 Authentication: JWT access token, 15-minute lifetime, signed RS256 with key from AWS Secrets Manager, delivered as HttpOnly Secure cookie with SameSite per AD-12. Claims: sub, role, iat, exp only. Binds: auth, all endpoints. Prevents: token forgery and inconsistent token checks. Rule: resource server validates signature and exp on every request; no role or scope data is trusted from the client. ACCEPTED RISK (user decision): logout and 30-minute inactivity are not enforced for access tokens; they take effect at refresh (see AD-7).
- (decision) AD-7 Refresh and session: opaque 256-bit refresh token in a separate HttpOnly cookie scoped to path /api/v1/auth. Stored in Redis as SHA-256 hash keyed by session id, with idle TTL 30 minutes reset on each rotation and absolute cap 8 hours stored in the record. Rotation on every refresh; reuse of a rotated token revokes the whole session. Logout deletes the Redis record. Binds: auth. Prevents: long-lived sessions, replayed refresh tokens, sessions surviving logout. Rule: refresh fails with 401 if the Redis record is missing, idle-expired, or past absolute cap.
- (decision) AD-8 Passwords and lockout: BCrypt cost 12. Account lockout after 5 consecutive failed logins for 15 minutes; failed-attempt counter and locked_until stored on the user row in PostgreSQL (durable, not Redis). Binds: auth, users. Prevents: inconsistent lockout state and weak hashing. Rule: login response is identical for unknown user and wrong password.
- (decision) AD-9 Authorization: three roles EMPLOYEE, MANAGER, HR_ADMIN. Role checks at the application facade, deny by default. Data scope resolver returns the visible employee set: self for employee, direct reports for manager, all for HR. Binds: all facades. Prevents: cross-team leakage and controller-level data queries. Rule: every facade method takes the caller identity and applies the scope resolver; out-of-scope records return 404 not 403 to avoid revealing existence.
- (decision) AD-10 API contract: REST under /api/v1; JSON; errors as RFC 9457 problem details; OpenAPI 3 generated from code and published; resource ids are UUIDs; leave dates are ISO 8601 LocalDate; timestamps are ISO 8601 UTC. Binds: all endpoints. Prevents: incompatible error and date shapes. Rule: breaking changes need /api/v2; additive changes stay in v1.
- (decision) AD-11 Leave day arithmetic: leave days = end minus start plus 1 calendar days, integers only, weekends and public holidays counted, no half-days in MVP. Computed only on the server. Binds: leave, balance. Prevents: client-side or inconsistent day counts. Rule: the day count stored on the request is the value used for balance checks and audit.
- (decision) AD-12 Cookies and CSRF: separate SPA on its own origin. Assumed same registrable domain (app and api subdomains), so cookies use SameSite=Strict; refresh cookie also Secure and HttpOnly. CORS allows only the SPA origin with credentials. State-changing requests require a CSRF token (double-submit cookie with X-XSRF-TOKEN header). Binds: auth, web adapter. Prevents: CSRF and cross-origin credential leaks. Rule: CORS allowlist is config, never wildcard. ASSUMPTION: same-site deployment; if not same-site, SameSite must change to None and the CSRF rule stays.
- (decision) AD-13 Balance ledger and negative-balance rule: balance is derived from an append-only balance_ledger table (entry: employee, leave type, delta days, reason, actor). Submission and approval lock the employee balance account row (SELECT FOR UPDATE) before checking available balance. Negative results rejected. HR adjustments write ledger entries with reason. Binds: balance, leave. Prevents: double-spend of balance under concurrent submissions and negative balances. Rule: no UPDATE or DELETE on balance_ledger (same trigger pattern as AD-5).
- (decision) AD-14 Leave request lifecycle: states PENDING, APPROVED, REJECTED, CANCELLED. Allowed transitions: submit to PENDING; PENDING to APPROVED or REJECTED (manager); PENDING to CANCELLED (employee). Modifications allowed only while PENDING and recorded before and after in audit. Rejection requires comment. Binds: leave, approval. Prevents: illegal state transitions and silent edits after decision. Rule: transition table is one domain enum map; any other transition throws. Concurrent decisions resolved by @Version optimistic lock on leave_request.
- (decision) AD-15 Notifications via transactional outbox: notification rows written in the same transaction as the state change. A scheduled publisher inside the core API reads pending outbox rows with FOR UPDATE SKIP LOCKED, publishes to Amazon SQS, marks sent. Delivery is at least once. Message contract: JSON with eventId UUID, eventType, schemaVersion, occurredAt, and ids only (no PII beyond employee id). Binds: outbox, notification worker. Prevents: lost or phantom emails. Rule: worker dedupes by eventId; contract changes bump schemaVersion.
- (decision) AD-16 Idempotency: POST submit and approval decision endpoints require Idempotency-Key header; key and response stored in PostgreSQL table with unique (actor, key), retained 24 hours. Binds: leave, approval endpoints. Prevents: duplicate requests from client retries. Rule: same key with different body returns 422.
- (decision) AD-17 Caching: Redis is the only cache. Permitted uses: refresh-session records (AD-7) and reference data (leave types, public holiday calendar) with 1-hour TTL, evicted on HR change. Leave, balance and audit data are never cached. Binds: all reads. Prevents: stale balances and approvals. Rule: cache keys prefixed by module name; eviction on every write to a cached source.
- (decision) AD-18 Schema migrations: Flyway SQL, forward-only, versioned. Migrations run as a one-off ECS task before the service rollout, not on application startup. Expand then contract for zero-downtime. Binds: database. Prevents: schema drift and rolling-deploy breakage. Rule: destructive change needs two releases.
- (decision) AD-19 Configuration and secrets: 12-factor, config from environment variables; secrets injected by ECS from AWS Secrets Manager; no secrets in the image or the repository. Binds: deployment. Prevents: secret leakage. Rule: startup fails if a required secret is missing.
- (decision) AD-20 Observability: JSON logs with request id (X-Request-Id, generated if absent) and user id, never passwords or tokens; Micrometer metrics; OpenTelemetry tracing. Binds: all. Prevents: unreadable logs and PII leakage. Rule: log filter masks Authorization and Cookie headers.
- (decision) AD-21 Hosting and runtime: stateless Docker image (Eclipse Temurin 21 base) on ECS Fargate, minimum 2 tasks across 2 availability zones behind an ALB that terminates TLS 1.2 or higher. RDS PostgreSQL Multi-AZ, ElastiCache Redis, SQS. Binds: deployment. Prevents: single points of failure and state stored in the container. Rule: no local file state; no sticky sessions.
- (decision) AD-22 Testing: unit tests for domain; integration tests with Testcontainers (PostgreSQL, Redis) and LocalStack or equivalent for SQS. ArchUnit enforces AD-3. Binds: all modules. Prevents: untested invariants (balance race, audit immutability). Rule: AD-5, AD-13 and AD-14 each have a dedicated integration test.
